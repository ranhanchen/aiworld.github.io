
AI 驱动的开放世界文字冒险游戏 功能设计方案 (FDS)
0. 技术栈与跨端自适应规范
0.1 核心技术架构
前端框架：采用 Vue 3 (Composition API) 或 React 19，利用信号机制（Signals）或组合式逻辑实现复杂的 UI 状态同步。

样式处理：采用 Tailwind CSS。利用其原子化类名构建“企业级极简” UI，通过 dark: 类名实现系统级深色模式适配。

持久化层：采用 Dexie.js。作为 IndexedDB 的高级封装库，处理大规模存档数据的 CRUD 及版本迁移。

并发处 #理：采用 Web Workers。将 AI 消息的结构化解析（JSON Parse）与历史记录的压缩算法逻辑移出主线程，确保长文本处理时 UI 帧率稳定在 60fps。

通信协议：采用 Fetch API (Stream)。支持流式传输，实现 AI 回复的逐字打印效果。

0.2 响应式与自适应设计 (Adaptive UI)
适配策略：采用 Mobile-First (移动端优先) 的响应式布局。

断点定义：

Mobile (< 768px)：全屏单列布局。侧边栏（存档、设置）转为底部抽屉或全屏遮罩层。

Tablet/Desktop (≥ 768px)：分栏布局。交互界面居中，两侧留白或通过侧边栏展示角色状态、地图信息。

交互适配：

触控端：增加交互元素的点击热区（Hit Target ≥ 44px），长按菜单辅以触感反馈（Haptic Feedback API）。

PC 端：支持全量快捷键操作（如 Ctrl+Enter 发送，Esc 关闭模态框），支持右键菜单替代长按。

视口单位应用：使用 dvl (Dynamic Viewport Height) 解决移动端浏览器工具栏遮挡底部输入框的问题，确保输入区始终可见。

0.3 环境兼容性与性能
浏览器支持：兼容主流浏览器最新 2 个版本（Chrome, Safari, Edge, Firefox）。

离线访问：配置 PWA (Progressive Web App) 规范，利用 Service Worker 缓存 UI 静态资源，确保在无网络环境下仍能进入主页查看历史存档。

资源加载：UI 图标采用 SVG 矢量图 或 Icon Font，严禁使用位图，以保证在不同 PPI 屏幕（Retina 屏）下的显示锐度。
1. 底层架构与技术选型约定
本地存储：采用 IndexedDB。
异步处理：采用 Web Worker 处理大体积数据的序列化、反序列化及后台对话压缩任务。
渲染机制：采用 Virtual List (虚拟列表) 技术渲染长对话。
网络通信：采用 Fetch API 与 Server-Sent Events (SSE) 处理大模型流式（Streaming）返回。
文件操作：采用 File API 与 Blob 接口实现存档的导入与导出。
2. 核心定义：“一条消息”的明确边界与数据结构
为了解决信息流渲染的歧义，对“消息（Message）”实体的物理层与展现层进行严格定义：
2.1 消息的定义与划分
数据层边界：一条消息等同于对话轮次中的一个完整“回合（Turn）”。即用户的单次发送内容为“一条用户消息”，AI 基于该次请求返回的完整结果为“一条 AI 消息”。
UI 层呈现边界：每一条消息在界面上独占一个外部容器（Message Block）。用户消息靠右展示；AI 消息靠左展示，且同一回合返回的 AI 消息绝不拆分为多个气泡，而是都在同一个大容器内进行多态排版。
2.2 AI 消息的内部渲染结构
由于要求区分语言、动作、场景等，AI 返回的每一条消息容器内部采用富文本多态组件渲染。
实现方式：在系统级 Prompt 中强制约束大模型输出严格的 JSON 数组格式（例如：[{type: "scene", content: "..."}, {type: "dialogue", speaker: "A", content: "..."}]），前端解析该数组，按顺序遍历并映射到不同的子 DOM 节点进行组装。
视觉规范：
scene (场景/旁白)：无背景色，居中对齐，字号偏小，无衬线字体，前后增加外边距作为段落分割。
dialogue (对话)：带气泡背景，衬线字体，文字颜色高亮，顶部附带角色名称标识符。
action (动作/神态)：无背景色，斜体字，紧贴在对应角色对话气泡的外部（上方或下方）。
system (系统提示/状态变化)：采用特殊强调色（如红色或金色），带有边框或居中加粗。
3. 各模块功能与交互设计详细方案
3.1 存档管理模块 (Save Management)
主页呈现：以网格或列表布局展示现有存档集合。包含封面图（可选）、存档名、当前回合数、最后游玩时间戳。
新建存档逻辑：
触发“新建”时，系统检索最后修改时间最新的存档记录。
提取该记录中的“设定元数据（Metadata）”。
自动填充至新存档的设定表单中，由用户确认或修改后正式创建。
导入导出功能：
提供批量操作复选框。
实现方式：导出时，将选中的 IndexedDB 数据记录序列化为单个 JSON 文件下载；导入时，读取上传的 JSON 文件并进行 Schema 校验，校验通过后写入本地数据库。
3.2 设定与生成模块 (Configuration Center)
表单分类设计：划分为网络配置、系统核心、世界观设定、角色面板、获胜条件五大选项卡。
AI 级联生成功能：
所有非系统配置类输入框（如背景、职业、技能）旁配置“自动生成”按钮。
实现方式：点击时，前端遍历表单状态（Form State），将当前已填写的非空字段打包为 Context Prompt，携带特定指令向 LLM 发起请求。将返回的纯文本（或结构化数据）赋值给目标输入框。
动态扩展字段：提供“添加自定义属性”按钮，支持用户新增 Key-Value 输入框组合。
3.3 交互主界面模块 (Game Interface)
布局：顶部悬浮状态栏（含设置、记忆面板入口），中部绝对定位的主信息流区，底部固定悬浮的输入控制区。
信息流加载与防卡顿：
初始化时仅渲染视口内的消息容器。
实现方式：监听主信息流容器的滚动事件，配合 IntersectionObserver。当顶部哨兵（Sentinel）节点进入视口时，触发静默加载，从本地数据库提取前 N 条消息并 prepend 至虚拟列表数据源。
长按上下文菜单：
用户对任意消息容器执行长按操作唤出菜单面板。
实现方式：绑定 contextmenu (PC) 与 touchstart/touchend 计时器 (移动端)。
操作分支：
复制：调用 navigator.clipboard.writeText()。
删除：从视图移除当前节点，并在数据库中删除对应的记录，重置相邻的回合索引。
重新生成：删除当前 AI 消息节点，提取上一条用户消息，重新发起 API 请求。
长短重写：提取当前 AI 消息的完整 JSON 及上文，拼接“更详细描述/更简略描述”的 Prompt 发起请求，结果返回后替换当前节点。
输入与发送机制：
底部 Textarea 支持自适应高度。
发送触发时，立即将用户消息推入视图列表，并写入数据库（状态：已发送）。
流式接收大模型响应，动态更新页面上最后一条 AI 消息容器的内容；接收完毕后写入数据库（状态：已完成）。
3.4 背景压缩与记忆算法模块 (Memory Management)
触发阈值：系统监听当前对话轮次（Round Index）。当索引到达 100 轮时触发。
执行切片：提取索引 [0, 50] 区间的消息数据（即距离当前最近的第 50 轮之前的所有内容）。
压缩执行逻辑：
实现方式：将“前次压缩摘要（若存在）” + “本次切片的 50 轮完整文本”打包发送至 LLM 的摘要专用通道。
获取返回的新摘要字符串，覆写数据库中的 Current_Summary 字段。
会话 Context 构建：在第 100 轮以后的常规对话交互中，每次发往 LLM 的负载结构固定为：系统设定参数 + Current_Summary + 最后 50 轮的原生消息记录。
标记与无感体验：
原先的 [0, 50] 轮消息仍在数据库保留。
在前端虚拟列表中，第 50 轮消息容器的视觉 UI 上追加一个唯一的 Icon（如书签标记）。
3.5 记忆管理与干预面板 (Memory Override Dashboard)
入口与展现：由主界面顶部右侧按钮唤出为全屏模态框（Modal）或侧边抽屉（Drawer）。
核心功能一：可视化干预：
显示多行文本编辑框（Textarea），双向绑定 Current_Summary 的数据。
用户可随意修改文本，点击“保存修改”后更新本地数据库记录，接管 AI 设定的摘要走向。
核心功能二：时空锚点跳转：
面板底部展示锚点信息条：“已压缩至第 50 轮：[消息内容前 20 字符...]”。
提供“定位至该节点”的按钮。
实现方式：点击后关闭面板，调用所在 DOM 节点的 scrollIntoView() 方法直接跳转视口。同时对该目标节点添加临时的 CSS 动画类（如 @keyframes pulse）以进行视觉高亮引导。
